## 保留的约定

- `star-vocab-progress-v1` 和原 word ID 不变，旧数据先保留，再兼容迁移。
- 导入必须完整校验后才合并；文件中没有的单词保留当前记录。主存储或 recovery 写失败时不改变原状态。
- 词库源为 roots / words JSON，含义关系由 manual-links 人工确认，wordlinks 是可重复生成的产物。不能凭拼写自动猜反义或押韵。
- 公开仓库不含原聊天、个人进度、私有快照、本机私人设置或密钥。
- 本项目不需要 fal；只有用户明确授权当前任务使用指定 fal 密钥生成时才可调用。
- 报告区分构建、桌面浏览器、小屏视口和真实手机。不要把模拟视口或普通 rAF 采样叫作真实手机性能验收。

## 制作与检查

```text
npm ci
npm test
npm run data:check
npm run learning:check
npm run build
npm run backup:check
```

改动学习状态时重点回归旧记录保护、写失败、导入与多个窗口合并。改动导航时重点回归同名 scope、手动切词、关闭、重复选词、关系词跳转以及词根/总览切换。改动场景时重点回归卸载清理、仅当前六词公转、背景标签页暂停和渲染故障回退。

浏览器诊断、截图和恢复证据另存 `.project-backups/attachments/`，不提交公开仓库。每次停工更新本文件，提交并推送代码，从实际使用的浏览器导出进度，再运行 `npm run backup -- --progress "导出文件路径"` 和 `npm run backup:verify`。没有新导出时沿用的旧文件不是当前浏览器最新记录。

## 原三阶段计划的接续

原设计为 [performance-architecture-design](superpowers/specs/2026-07-19-performance-architecture-design.md)。顺序为 [Phase 1](superpowers/plans/2026-07-19-phase-1-forcegraph-stabilization.md) 稳住现有场景、[Phase 2](superpowers/plans/2026-07-19-phase-2-sharded-catalog.md) 分片与预计算、[Phase 3](superpowers/plans/2026-07-19-phase-3-batched-renderer.md) 批量渲染及未来旧实现退出。

这些计划描述的是旧版代码，下一次制作先核对本轮实现与测试再逐项接续，不能机械照抄旧错误数量或依赖版本。当前仍用 ForceGraph 外层管理场景，没有完整实现设计中的 SceneCoordinator / FrameScheduler / CatalogRepository；也没有词库分片或批量绘制。

需要正式三阶段验收时，仍遵守原顺序、真实性能矩阵、资源与回退门槛。Phase 2 结束需要真实 Pixel 7a D3，桌面模拟不替代。Phase 3B 删除旧实现必须等待两次稳定发布及至少十四天观察，并遵守旧版本/数据三十天保留条件。本轮不满足这些未来删除门槛。

下一次优先依据用户实际使用反馈完善，不声称项目永久无 bug。原聊天窗口迁移需 Codex 的连接/转交功能；私有可读对话副本可供新聊天接续，不保证重新导入为原窗口。
